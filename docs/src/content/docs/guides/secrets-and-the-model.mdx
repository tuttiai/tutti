This page describes what Tutti does today to keep API keys and tokens away from the model and from event listeners, what it does not do, and what you should do yourself. Every statement here is backed by a test or a recorded limit in the repository.

## The patterns `SecretsManager` matches

`SecretsManager.redact` replaces any text matching one of five patterns with `[REDACTED]`. `SecretsManager.redactObject` does the same for any value by converting it to JSON, redacting the string and parsing it back, so keys nested in objects and arrays are covered too.

| Format | Pattern | Example shape |
| --- | --- | --- |
| Anthropic | `sk-ant-[a-zA-Z0-9-_]{20,}` | `sk-ant-…` |
| OpenAI | `sk-[a-zA-Z0-9]{20,}` | `sk-…` |
| GitHub classic token | `ghp_[a-zA-Z0-9]{36}` | `ghp_…` |
| Google API key | `AIza[a-zA-Z0-9-_]{35}` | `AIza…` |
| Bearer token | `Bearer [a-zA-Z0-9-_.]{20,}` | `Bearer …` |

A key is only stripped when it fits one of these patterns exactly. The [known limits](#known-limits) below list shapes of these formats that do not fit.

## Event payloads

`EventBus.emit` runs `SecretsManager.redactObject` once on every event, before any listener is called. Both typed listeners (`on`) and wildcard listeners (`onAny`) receive the redacted copy, never the original.

:::note
This covers what your listeners receive, not what is sent to the model. An `llm:request` or `tool:end` event is redacted, but the request Tutti sends to the provider and the tool result inside it are not changed by this step.
:::

Tested in `packages/core/tests/secret-redaction-events.test.ts`.

## Errors thrown by a tool

When a tool throws, `AgentRunner` passes the message through `SecretsManager.redact` before it goes back to the model as a tool result with `is_error: true`. The run carries on, and the model sees `[REDACTED]` in place of a matching key.

This is the only path to the model that Tutti redacts.

Tested in `packages/core/tests/secret-redaction-tool-errors.test.ts`, which records the request the model receives after the tool throws.

## What the sandbox inherits

The [sandbox voice](/voices/sandbox/) does not hand its child processes the agent's whole environment. `childEnv` in `voices/sandbox/src/utils/child-env.ts` reads each name on a fixed allowlist through `SecretsManager.optional` and passes on only those that are set:

`PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `LANG`, `LC_ALL`, `LC_CTYPE`, `TZ`, `TMPDIR`, `TERM`, `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`, `http_proxy`, `https_proxy`, `no_proxy`, `NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE`.

The voice's `env` option is added on top, and its values win over inherited ones. `NODE_ENV` is left out on purpose. The allowlist is fixed in the code; it is not configurable.

Tested in `voices/sandbox/tests/child-env-allowlist.test.ts` and `voices/sandbox/tests/child-env.test.ts`.

:::caution
This is not isolation. The sandboxed process runs as the server's own user, so code that sets out to can still read every credential the server holds from `/proc/1/environ`. This limit is recorded in [tutti#29](https://github.com/tuttiai/tutti/pull/29). Only a container that holds no credential is safe to give `shell`.
:::

## Known limits

Today, the following are not redacted:

- **Successful tool results.** The content a tool returns goes to the model as it is, wrapped by `PromptGuard` but not passed through `SecretsManager`.
- **Cached tool results.** A result served from the tool cache takes the same path as a successful one.
- **Errors a tool returns instead of throwing.** A result of `{ is_error: true }` is treated like any other returned result, so its content is not redacted.
- **Lowercase or uppercase Bearer.** `bearer …` and `BEARER …` are not matched, because the pattern is case-sensitive.
- **Bearer tokens with `+`, `/` or `=`.** Base64 tokens containing these characters survive in part, or whole if one of them falls in the first 20 characters.
- **Newer OpenAI key shapes.** `sk-proj-`, `sk-svcacct-` and `sk-admin-` keys are not matched, because the hyphen after the prefix stops the `sk-` pattern.
- **Keys split across stream chunks.** Each `token:stream` event is redacted on its own, so a key split across two chunks gets through.
- **Other formats.** Any key or token that does not fit one of the five patterns above is not covered.
- **The server's environment from inside the sandbox.** See the caution above and [tutti#29](https://github.com/tuttiai/tutti/pull/29).

The matching gaps are recorded as pending tests in `packages/core/tests/secret-redaction-events.test.ts` and `packages/core/tests/secret-redaction-tool-errors.test.ts`.

## What to do today

- **Do not return secrets in tool results.** Strip credentials from anything a tool returns, including headers and config dumps.
- **Throw rather than return `is_error`** when an error message could contain a key, so it passes through `SecretsManager.redact`.
- **Keep the sandbox `env` option to what the code needs**, and never put a credential in it: it is passed straight to the sandboxed process.
- **Do not treat the sandbox as a boundary** for credentials held by the server.
- **Keep keys out of strings that can reach the model**, especially keys in formats the patterns above do not match.

For the other security layers, see the [Security guide](/guides/security/).
