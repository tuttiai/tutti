Tutti ships with five built-in LLM providers. They all implement the same `LLMProvider` interface, so you can swap them with a single line change.

## Anthropic (Claude)

```ts
import { AnthropicProvider } from "@tuttiai/core";

const provider = new AnthropicProvider();
// or with explicit key:
const provider = new AnthropicProvider({ api_key: "sk-ant-..." });
```

| Option | Default | Description |
| ------ | ------- | ----------- |
| `api_key` | `ANTHROPIC_API_KEY` env var | API key |

**Prompt caching** is on for every request. The provider marks the end of the system prompt (or the last tool, when there is no system prompt) and the end of the latest message, so each turn of a run reads everything before it from Anthropic's prompt cache at a tenth of the input rate and pays full price only for what it adds. A prompt shorter than the model's caching minimum is simply not cached. `usage.input_tokens` counts every prompt token; `usage.cache_read_input_tokens` and `usage.cache_creation_input_tokens` say how many of them were read from and written to the cache.

**Models:** `claude-sonnet-4-20250514`, `claude-opus-4-20250514`, `claude-haiku-4-20250514`

## OpenAI (GPT)

```ts
import { OpenAIProvider } from "@tuttiai/core";

const provider = new OpenAIProvider();
// or with custom config:
const provider = new OpenAIProvider({
  api_key: "sk-...",
  base_url: "https://your-azure-endpoint.openai.azure.com",
});
```

| Option | Default | Description |
| ------ | ------- | ----------- |
| `api_key` | `OPENAI_API_KEY` env var | API key |
| `base_url` | OpenAI default | Custom endpoint (Azure, proxies) |

**Models:** `gpt-4o`, `gpt-4o-mini`, or any model your endpoint supports.

## Google Gemini

```ts
import { GeminiProvider } from "@tuttiai/core";

const provider = new GeminiProvider();
// or with explicit key:
const provider = new GeminiProvider({ api_key: "AIza..." });
```

| Option | Default | Description |
| ------ | ------- | ----------- |
| `api_key` | `GEMINI_API_KEY` env var | API key |

**Models:** `gemini-2.0-flash` (default), `gemini-2.0-pro`

:::caution
Gemini requires an API key — it will throw at construction time if neither `api_key` nor `GEMINI_API_KEY` is set.
:::

## OpenRouter (300+ models, one API key)

OpenRouter is an OpenAI-compatible aggregator that routes requests to 300+ models across providers (Anthropic, OpenAI, Google, Meta, Mistral, …) through a single API key. Use it when you want to try many models without juggling provider-specific keys, or when you want OpenRouter's cross-provider failover.

```ts
import { OpenRouterProvider } from "@tuttiai/core";

const provider = new OpenRouterProvider();
// or with explicit options:
const provider = new OpenRouterProvider({
  api_key: "sk-or-...",
  http_referer: "https://example.com",  // opt-in attribution for openrouter.ai/rankings
  x_title: "My App",                     // opt-in attribution for openrouter.ai/rankings
  route: "fallback",                     // retry against backup providers on error
  models: ["anthropic/claude-sonnet-4", "openai/gpt-4o"], // ordered fallback list
});
```

| Option | Default | Description |
| ------ | ------- | ----------- |
| `api_key` | `OPENROUTER_API_KEY` env var | API key |
| `base_url` | `https://openrouter.ai/api/v1` | Override for self-hosted OpenRouter forks |
| `http_referer` | unset | Opt-in `HTTP-Referer` attribution header |
| `x_title` | unset | Opt-in `X-Title` attribution header |
| `route` | unset | `'fallback'` enables OpenRouter's cross-provider retry |
| `models` | unset | Ordered list of fallback model ids |

**Models:** namespaced — e.g. `anthropic/claude-sonnet-4`, `openai/gpt-4o`, `google/gemini-2.0-flash`, `meta-llama/llama-3.3-70b-instruct`. See [openrouter.ai/models](https://openrouter.ai/models) for the live catalogue.

**Cost reporting:** OpenRouter returns per-call USD cost inline via its `usage: { include: true }` extension. The cost is surfaced on `ChatResponse.usage.cost_usd` and `StreamChunk.usage.cost_usd` — no second `/generation` round trip required. Your `RunCostStore`-backed daily/monthly budgets work identically to the native providers.

**Errors:** 401 → `AuthenticationError`, 429 → `RateLimitError` (with `Retry-After` parsing), other HTTP errors → `ProviderError` with `status` preserved. Same shape as the other providers, so retry/backoff policy is unchanged.

## Claude Code (your own Claude subscription)

`ClaudeCodeProvider` answers through a locally installed [Claude Code](https://docs.anthropic.com/en/docs/claude-code) CLI, running `claude -p` once per turn. It uses whatever login that CLI already holds, so on your own machine your agents run against your Claude Pro or Max plan instead of per-token API billing.

```ts
import { ClaudeCodeProvider } from "@tuttiai/core";

const provider = new ClaudeCodeProvider();
// or with explicit options:
const provider = new ClaudeCodeProvider({
  command: "/usr/local/bin/claude", // default: `claude` on PATH
  timeout_ms: 300_000,              // default: 10 minutes per turn
});
```

| Option | Default | Description |
| ------ | ------- | ----------- |
| `command` | `claude` | The CLI to run |
| `timeout_ms` | `600000` | Kill a turn that runs longer than this |
| `cwd` | the OS temp directory | Working directory for the CLI |
| `reuse_sessions` | `true` | Resume the session that holds a conversation and send only what is new. `false` keeps nothing on disk and sends the whole transcript every turn |
| `runner` | spawns the CLI | Replace the process runner, for tests |

**Signing in:** Tutti never reads or stores a credential for this provider. Sign the CLI in yourself, either interactively (`claude`, then `/login`) or, in a container, with a long-lived token: run `claude setup-token` once and pass the result as `CLAUDE_CODE_OAUTH_TOKEN`. **If `ANTHROPIC_API_KEY` is set, Claude Code uses it and bills the API**, and the provider logs a warning saying so.

**How tools work:** every Claude Code built-in tool, MCP server, hook, plugin and `CLAUDE.md` is switched off (`--tools "" --safe-mode --strict-mcp-config`), so the CLI behaves as a plain model. The model answers through structured output, either with its final text or with calls to your agent's tools, which Tutti's runner then executes exactly as it does for any other provider. Tool names are constrained to the ones offered.

**Sessions and caching:** Claude Code keys its prompt cache to its own session, so a call that starts a new session and re-sends the conversation is written to the cache in full and reads nothing back, on every turn. Measured on 2026-10-05 with CLI 2.1.263, three turns of a growing conversation each wrote about 8,200 tokens and read none. So the provider starts each conversation as a session with a known id and, on the next turn, resumes it (`--resume`) sending only the messages added since its last reply. The same measurement then read about 8,100 tokens from the cache and wrote about 145. Sessions are kept as files under the CLI's own `~/.claude/projects`, as an interactive session's are. The provider sends the whole transcript to a new session whenever it cannot resume safely: the history was rewritten (by a hook, or by `context` shortening), the tools or system prompt changed, the session is more than an hour old, the CLI no longer has it, or another call is already using it.

**Limits:**
- Each turn is a fresh `claude -p` process, which adds a second or two of start-up per turn.
- `max_tokens`, `temperature` and `stop_sequences` are not supported by the CLI and are ignored.
- `stream()` yields the reply once it is complete, not token by token.
- Usage counts against your plan's rolling limits, shared with your own Claude Code sessions. A reached limit surfaces as `RateLimitError`.
- `usage.cost_usd` is left unset. Token counts are reported, so cost estimates and `max_cost_usd` still work, but they price list rates your plan does not charge.

:::caution
This provider is for running **your own** agents on **your own** machine. Anthropic's terms do not permit serving other people through a personal Claude subscription. For anything that answers other users, use `AnthropicProvider` with an API key.
:::

**In the Docker image**, build with the CLI and select the provider:

```bash
docker build --build-arg CLAUDE_CODE_VERSION=2.1.284 -t tutti-server:claude-code .
docker run -p 3847:3847 \
  -e TUTTI_API_KEY=key \
  -e TUTTI_PROVIDER=claude-code -e TUTTI_MODEL=claude-sonnet-5 \
  -e CLAUDE_CODE_OAUTH_TOKEN=... \
  tutti-server:claude-code
```

**Errors:** a 401 or 403 becomes `AuthenticationError`; a 429 or a reached usage limit becomes `RateLimitError`; a missing CLI, a timeout or any other failure becomes `ProviderError`, with `status` kept when the API gave one.

## Switching providers

Just change the `provider` in your score:

```ts title="tutti.score.ts"
import { OpenAIProvider, defineScore } from "@tuttiai/core";

export default defineScore({
  provider: new OpenAIProvider(),
  default_model: "gpt-4o",
  agents: {
    assistant: {
      name: "assistant",
      system_prompt: "You are helpful.",
      voices: [],
    },
  },
});
```

## Per-agent model overrides

The `default_model` in the score applies to all agents. Individual agents can override it:

```ts
agents: {
  fast: {
    name: "Fast Agent",
    model: "claude-haiku-4-20250514",  // cheap and fast
    system_prompt: "Quick answers only.",
    voices: [],
  },
  smart: {
    name: "Smart Agent",
    model: "claude-opus-4-20250514",   // expensive and thorough
    system_prompt: "Think deeply.",
    voices: [],
  },
}
```

## Token budget by model

Different models have different pricing. The `TokenBudget` knows about each model's rates:

| Model | Input $/M tokens | Output $/M tokens |
| ----- | ---------------- | ----------------- |
| `claude-sonnet-4-20250514` | $3.00 | $15.00 |
| `claude-opus-4-20250514` | $15.00 | $75.00 |
| `claude-haiku-4-20250514` | $0.25 | $1.25 |
| `gpt-4o` | $2.50 | $10.00 |
| `gemini-2.0-flash` | $0.10 | $0.40 |

```ts
{
  assistant: {
    model: "claude-sonnet-4-20250514",
    budget: { max_cost_usd: 0.50 },  // Stop at 50 cents
    // ...
  },
}
```

## Routing between providers

For agent systems where different turns benefit from different models, see the [Smart Routing guide](./smart-routing). The `SmartProvider` from `@tuttiai/router` wraps any of the providers above and picks the cheapest one that can handle each call.
