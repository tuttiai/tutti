Tutti supports multi-agent workflows where an **orchestrator** routes tasks to **specialist** agents. Each specialist has its own system prompt, tools, and constraints.

## The pattern

```
User → Orchestrator → [Coder, PM, QA] → Orchestrator → User
```

The orchestrator receives the user's request, decides which specialist to delegate to, and summarizes the results.

## Define the score

```ts title="tutti.score.ts"
import { AnthropicProvider, defineScore } from "@tuttiai/core";
import { FilesystemVoice } from "@tuttiai/filesystem";

export default defineScore({
  name: "dev-team",
  provider: new AnthropicProvider(),
  default_model: "claude-sonnet-5-5",
  entry: "orchestrator",
  agents: {
    orchestrator: {
      name: "Orchestrator",
      role: "orchestrator",
      system_prompt: `You receive user requests and delegate them to the right specialist.
Think about which specialist is best suited before delegating.
Summarize results clearly.`,
      voices: [],
      delegates: ["coder", "pm", "qa"],
    },
    coder: {
      name: "Coder",
      role: "specialist",
      system_prompt: `You are a senior TypeScript developer.
Write clean, tested, production-ready code.`,
      voices: [new FilesystemVoice()],
      permissions: ["filesystem"],
    },
    pm: {
      name: "Product Manager",
      role: "specialist",
      system_prompt: `You are a senior product manager.
Write clear specs, break down features, think about UX.`,
      voices: [],
    },
    qa: {
      name: "QA Engineer",
      role: "specialist",
      system_prompt: `You are a thorough QA engineer.
Think about edge cases, write test plans, identify bugs.`,
      voices: [],
    },
  },
});
```

## Run with the AgentRouter

```ts title="run.ts"
import { AgentRouter } from "@tuttiai/core";
import score from "./tutti.score.js";

const router = new AgentRouter(score);

// Subscribe to delegation events
router.events.on("delegate:start", (e) => {
  console.log(`[delegation] ${e.from} → ${e.to}: "${e.task}"`);
});
router.events.on("delegate:end", (e) => {
  console.log(`[delegation] ${e.to} finished (${e.output.length} chars)`);
});

const result = await router.run(
  "Write a function that reverses a string and save it to reverse.ts",
);
console.log(result.output);
```

## How it works

1. `AgentRouter` wraps `TuttiRuntime` and injects a `delegate_to_agent` tool into the orchestrator
2. The orchestrator's system prompt is enhanced with descriptions of available specialists
3. When the orchestrator calls `delegate_to_agent({ agent_id: "coder", task: "..." })`, the router runs the specialist agent and returns its output
4. The orchestrator can delegate to multiple specialists in sequence

## Delegation events

Listen to these events to track the flow:

| Event | Fields | When |
| ----- | ------ | ---- |
| `delegate:start` | `from`, `to`, `task` | Orchestrator delegates to a specialist |
| `delegate:delta` | `tool_call_id`, `from`, `to`, `text`, `session_id`, `parent_session_id`, `root_session_id`, `path`, `depth` | A streaming specialist produced a chunk of output |
| `delegate:end` | `from`, `to`, `output` | Specialist returns its result |

## Stream a specialist's output

While a `delegate_to_agent` call runs, a specialist with `streaming: true` has each chunk of its output forwarded onto the router's event stream as a `delegate:delta` event. You can show the specialist's work live from the same stream, with no second subscription:

```ts title="stream.ts"
import { AgentRouter } from "@tuttiai/core";
import score from "./tutti.score.js"; // set `streaming: true` on the specialists

const router = new AgentRouter(score);
const panels = new Map<string, string>();

router.events.on("delegate:delta", (e) => {
  // One panel per tool call, so parallel delegations stay apart.
  panels.set(e.tool_call_id, (panels.get(e.tool_call_id) ?? "") + e.text);
  process.stdout.write(`[${e.to} ${e.tool_call_id}] ${e.text}\n`);
});

const result = await router.run("Write a function that reverses a string");
console.log(result.output);
```

To follow one run among several on a shared runtime, keep the deltas whose `root_session_id` is that run's session id.

- **Order.** A call's deltas arrive after its `delegate:start` and before its `delegate:end`, in the order the specialist wrote them. On success, joining them gives the specialist's output. Parallel calls can interleave, and `tool_call_id` tells them apart.
- **Nesting.** When a specialist delegates in turn, its own specialist's deltas reach the same stream. `path` lists the tool call ids from the top-level call down to the one that produced the text, and `depth` is its length: 1 for a direct specialist, 2 for its specialist. `parent_session_id` is the session of the agent that made the call.
- **Errors and aborts.** When a specialist fails, or the run's `AbortSignal` fires, its deltas stop and none arrives after the call ends. The text already sent is not taken back. As before, no `delegate:end` is sent in either case.
- **Specialists that do not stream** send no deltas; their output arrives in `delegate:end` as before.
- **Redaction.** Each chunk goes through `SecretsManager` redaction before it is emitted. Redaction works chunk by chunk, so a secret split across two chunks is not caught.

## Tips

:::tip
Give each specialist a clear, focused system prompt. The orchestrator works best when it can match tasks to well-defined roles.
:::

:::caution
Each delegation is a separate agent run with its own token usage. Set `budget` on specialists to prevent runaway costs.
:::

## Nested delegation

By default only the entry agent delegates, and a specialist's `delegates[]` is ignored. Set `nested_delegation: true` on the score to let a specialist delegate in turn:

```ts title="tutti.score.ts"
export default defineScore({
  provider: new AnthropicProvider(),
  entry: "orchestrator",
  nested_delegation: true,
  agents: {
    orchestrator: { name: "Orchestrator", system_prompt: "Route requests.", voices: [], delegates: ["lead"] },
    lead: { name: "Tech Lead", system_prompt: "Plan the work, then hand it on.", voices: [], delegates: ["coder"] },
    coder: { name: "Coder", system_prompt: "Write the code.", voices: [] },
  },
});
```

With the option on, every agent that lists `delegates[]` gets the `delegate_to_agent` tool and a prompt naming its specialists. Each delegation emits its own `delegate:start` and `delegate:end`, with `from` set to the agent that delegated. `AgentRouter` checks the whole delegation graph when it is constructed. It throws if a `delegates[]` id names no agent, or if a chain loops back on itself (for example `lead -> coder -> lead`), and the error names the id or the cycle.

## Parallel fan-out

When you want multiple agents to look at the same input **simultaneously** (e.g. a bull analyst and a bear analyst, or several reviewers), use parallel execution instead of sequential delegation.

### Declarative parallel entry

Set `entry` to a `ParallelEntryConfig` and `router.run(input)` will fan the input out to every listed agent at once, returning a merged `AgentResult`:

```ts title="tutti.score.ts"
export default defineScore({
  provider: new AnthropicProvider(),
  entry: { type: "parallel", agents: ["bull", "bear"] },
  agents: {
    bull: { name: "Bull", system_prompt: "...", voices: [] },
    bear: { name: "Bear", system_prompt: "...", voices: [] },
  },
});
```

### Programmatic `runParallel()`

For per-agent inputs, timeouts, and rich rollup metrics, call `runParallel` directly:

```ts
const router = new AgentRouter(score);

const results = await router.runParallel(
  [
    { agent_id: "bull", input: "AAPL at current valuation" },
    { agent_id: "bear", input: "AAPL at current valuation" },
  ],
  { timeout_ms: 30_000 },
);

for (const [agentId, result] of results) {
  console.log(`${agentId}: ${result.output}`);
}
```

- All agents start at once via `Promise.all`; each gets its own session.
- If one agent fails, the others still complete: the failure is surfaced as a synthetic `[error]` result in the returned map (so callers can see which agent broke).
- `timeout_ms` limits how long `runParallel` waits for each agent. An agent that takes longer gets an `[error]` result saying it exceeded the timeout, and the call returns without its output. The agent is not cancelled: it keeps running in the background, its events still reach `router.events`, and it may keep calling the model and spending until it finishes. Its usage is not counted in `runParallelWithSummary`'s totals. To cap what it can spend, set `budget.max_cost_usd` on the agent; the run then stops at the start of its next turn once the cap is reached, so a model call already in progress still completes.

For the full aggregate (merged output + total usage + total cost + duration) use `runParallelWithSummary`, which returns a `ParallelAgentResult`.

### Parallel events

| Event | Fields | When |
| ----- | ------ | ---- |
| `parallel:start` | `agents` | Before the batch dispatches |
| `parallel:complete` | `results` (agent IDs that succeeded) | After every agent has settled |
