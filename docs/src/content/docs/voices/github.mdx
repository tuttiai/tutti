The GitHub voice gives agents access to the GitHub API — issues, pull requests, repositories, and code search.

It can also take a change all the way to a pull request with no git binary or shell: `create_branch`, then `commit_files`, then `create_pull_request`. All three are marked `destructive: true`, so they wait for human approval by default.

It can read CI on a pull request too: `list_pull_request_checks` reports every check run and commit status with an overall verdict, and `get_check_run_log` returns the tail of a failed GitHub Actions job's log. Both are read-only.

And it can keep a pull request moving without a person: `edit_file` changes part of a file without the agent holding all of it, `update_pull_request` and `mark_ready_for_review` tidy the PR, `update_pull_request_branch` brings it up to date with its base, `rerun_workflow_job` retries a failed or cancelled CI job, `get_commit` shows what one commit did, and `create_review` records a reviewer's verdict on GitHub. Every one that writes is marked `destructive: true`.

## Installation

```bash
npx tutti-ai add github
```

## Required permissions

```ts
permissions: ["network"]
```

## Required environment variables

| Var | Description |
| --- | ----------- |
| `GITHUB_TOKEN` | GitHub personal access token (or fine-grained token) |

Add to your `.env`:

```bash title=".env"
GITHUB_TOKEN=ghp_your_token_here
```

## Configuration

```ts
// Default: reads GITHUB_TOKEN from env
new GitHubVoice()

// Explicit token
new GitHubVoice({ token: "ghp_..." })
```

## Tool reference

| Tool | Description | Key inputs |
| ---- | ----------- | ---------- |
| `list_issues` | List issues in a repo | `owner`, `repo`, `state`, `labels`, `limit` |
| `get_issue` | Get issue details | `owner`, `repo`, `issue_number` |
| `create_issue` | Create a new issue | `owner`, `repo`, `title`, `body`, `labels` |
| `comment_on_issue` | Add a comment | `owner`, `repo`, `issue_number`, `body` |
| `list_pull_requests` | List PRs | `owner`, `repo`, `state`, `limit` |
| `get_pull_request` | Get PR details | `owner`, `repo`, `pr_number` |
| `get_commit` | Read one commit and its patches | `owner`, `repo`, `sha` |
| `list_pull_request_checks` | List CI check runs and commit statuses on a PR | `owner`, `repo`, `pr_number` |
| `get_check_run_log` | Get the tail of a GitHub Actions job log | `owner`, `repo`, `check_run_id`, `tail_lines` |
| `rerun_workflow_job` | Re-run a failed or cancelled Actions job (destructive) | `owner`, `repo`, `check_run_id` |
| `create_branch` | Create a branch (destructive) | `owner`, `repo`, `branch`, `from` |
| `commit_files` | Commit files and deletions to a branch (destructive) | `owner`, `repo`, `branch`, `message`, `files`, `deletions` |
| `edit_file` | Replace exact text in one file on a branch (destructive) | `owner`, `repo`, `branch`, `path`, `message`, `edits` |
| `create_pull_request` | Open a PR from an existing branch (destructive) | `owner`, `repo`, `title`, `head`, `base`, `body`, `draft` |
| `update_pull_request` | Change a PR's title or description (destructive) | `owner`, `repo`, `pr_number`, `title`, `body` |
| `update_pull_request_branch` | Merge the base into a PR's branch (destructive) | `owner`, `repo`, `pr_number`, `expected_head_sha` |
| `mark_ready_for_review` | Take a draft PR out of draft (destructive) | `owner`, `repo`, `pr_number` |
| `create_review` | Approve, request changes or comment (destructive) | `owner`, `repo`, `pr_number`, `event`, `body`, `commit_id` |
| `get_file_contents` | Get a file, one page at a time | `owner`, `repo`, `path`, `ref`, `offset`, `limit` |
| `search_code` | Search code across GitHub | `query`, `limit` |
| `list_repositories` | List repos for a user/org | `owner`, `type`, `limit` |
| `get_repository` | Get repo details | `owner`, `repo` |

### list_issues

| Input | Type | Default | Description |
| ----- | ---- | ------- | ----------- |
| `owner` | `string` | — | Repository owner |
| `repo` | `string` | — | Repository name |
| `state` | `"open" \| "closed" \| "all"` | `"open"` | Filter by state |
| `labels` | `string?` | — | Comma-separated labels |
| `limit` | `number` | `20` | Max results (1-100) |

### create_issue

| Input | Type | Default | Description |
| ----- | ---- | ------- | ----------- |
| `owner` | `string` | — | Repository owner |
| `repo` | `string` | — | Repository name |
| `title` | `string` | — | Issue title |
| `body` | `string?` | — | Issue body (Markdown) |
| `labels` | `string[]?` | — | Labels to apply |

### list_pull_request_checks

| Input | Type | Default | Description |
| ----- | ---- | ------- | ----------- |
| `owner` | `string` | - | Repository owner |
| `repo` | `string` | - | Repository name |
| `pr_number` | `number` | - | Pull request number |

Resolves the pull request's head commit and lists every check run on it (name, status, conclusion, start and completion times, link, `check_run_id`, and the output title and summary, truncated) and every commit status. It opens with one overall line, for example `Overall: 3 passed, 1 failed, 0 pending, 0 skipped (verdict: failing)`. The verdict is `green` only when at least one check exists and none failed or is still running, so an agent gating its work on CI never reads "no CI" as a pass. Read-only.

### get_check_run_log

| Input | Type | Default | Description |
| ----- | ---- | ------- | ----------- |
| `owner` | `string` | - | Repository owner |
| `repo` | `string` | - | Repository name |
| `check_run_id` | `number` | - | A `check_run_id` from `list_pull_request_checks`; for GitHub Actions it is the job id |
| `tail_lines` | `number?` | `150` | Lines to return from the end of the log, at most `1000` |

Downloads a GitHub Actions job's log and returns only its last lines, capped at 40,000 characters, so an agent can see why a build or test failed. A check run from any other app has no log behind the API and comes back as an error naming its details page. A log that has expired, or a job that has not finished, is reported with a hint. The token needs read access to Actions. Read-only.

### create_branch

| Input | Type | Default | Description |
| ----- | ---- | ------- | ----------- |
| `owner` | `string` | — | Repository owner |
| `repo` | `string` | — | Repository name |
| `branch` | `string` | — | Name of the new branch |
| `from` | `string?` | default branch | Existing branch to start from |

A branch that already exists comes back as an error pointing at `commit_files`.

### commit_files

| Input | Type | Default | Description |
| ----- | ---- | ------- | ----------- |
| `owner` | `string` | — | Repository owner |
| `repo` | `string` | — | Repository name |
| `branch` | `string` | — | Existing branch to commit onto |
| `message` | `string` | — | Commit message |
| `files` | `{ path, content }[]` | `[]` | Files to write, each with its full new UTF-8 content (1 MB max each) |
| `deletions` | `string[]` | `[]` | Paths to delete |

Writes one commit through the Git Data API and fast-forwards the branch; it never force-pushes, so a branch that moved in the meantime is reported and left alone. At least one entry and at most 100 across `files` and `deletions`. Every path is checked before any request: absolute paths, `..`, backslashes, empty segments, anything inside `.git`, and a path listed twice are all refused.

**It refuses the repository's default branch.** Call `create_branch` first, commit onto that, then `create_pull_request`, so an agent's change always reaches the default branch through a reviewed pull request.

### edit_file

| Input | Type | Default | Description |
| ----- | ---- | ------- | ----------- |
| `owner` | `string` | — | Repository owner |
| `repo` | `string` | — | Repository name |
| `branch` | `string` | — | Existing branch to commit onto |
| `path` | `string` | — | Existing file to change |
| `message` | `string` | — | Commit message |
| `edits` | `{ old_text, new_text }[]` | — | Replacements applied in order, 1 to 50 |

Reads the whole file at the branch head, applies each replacement to the result of the one before, and commits the file onto the branch, fast-forwarding it as `commit_files` does. Each `old_text` must occur exactly once: text that is missing or appears more than once refuses the whole call and nothing is committed. Because the file is edited whole on the server, an agent can change a file it has read only part of. Refuses the default branch and the same paths `commit_files` refuses.

### get_file_contents

| Input | Type | Default | Description |
| ----- | ---- | ------- | ----------- |
| `owner` | `string` | — | Repository owner |
| `repo` | `string` | — | Repository name |
| `path` | `string` | — | File or directory path |
| `ref` | `string?` | default branch | Branch, tag or SHA |
| `offset` | `number` | `1` | First line to return, 1-based |
| `limit` | `number?` | — | Most lines to return, at most `5000` |

A page also stops at 40,000 characters. Every file read opens with a line such as `[src/a.ts @ main: lines 1-400 of 1,212 (48,310 bytes), PARTIAL: next offset=401. …]`, or `complete` when the page is the whole file, so a caller always knows when it holds only part. Files over 1 MB are read as blobs and paged rather than refused.

### rerun_workflow_job

Takes the `check_run_id` from `list_pull_request_checks`, which for GitHub Actions is the job id, and re-runs that job and the jobs depending on it. Only a job that finished as failed, cancelled or timed out is re-run; one still queued or in progress is refused with the advice to wait, because a slow job is not a stuck one. The token needs write access to Actions.

### create_review

`event` is `APPROVE`, `REQUEST_CHANGES` or `COMMENT`, and `body` is required. An approval counts towards a repository's required reviews wherever the connection's account is not the pull request's author; GitHub refuses an account approving or requesting changes on its own pull request, and the tool then points at `COMMENT`.

### search_code

| Input | Type | Default | Description |
| ----- | ---- | ------- | ----------- |
| `query` | `string` | — | GitHub code search query |
| `limit` | `number` | `10` | Max results |

## Example

```ts title="tutti.score.ts"
import { AnthropicProvider, defineScore } from "@tuttiai/core";
import { GitHubVoice } from "@tuttiai/github";

export default defineScore({
  provider: new AnthropicProvider(),
  agents: {
    triager: {
      name: "Issue Triager",
      model: "claude-sonnet-4-20250514",
      system_prompt: `You help triage GitHub issues. When asked about a repo,
list the open issues, summarize them, and suggest priorities.`,
      voices: [new GitHubVoice()],
      permissions: ["network"],
    },
  },
});
```

```
> What are the top open issues in facebook/react?

  Done: list_issues

2. #28089 — Server Components streaming error handling (enhancement)
...
```
