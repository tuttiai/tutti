The Notion voice gives an agent the pages and databases a Notion internal integration has been
given: search them, read a page's properties and body, query a database, and create, append to,
update and archive pages. It calls Notion's REST API with `fetch`, pinned to
`Notion-Version: 2022-06-28`.

Notion shows an integration nothing until a person shares a page with it through the page's
**Connections** menu, so what the agent can reach is decided in Notion, page by page.

## Installation

```bash
npx tutti-ai add notion
```

## Required permissions

```ts
permissions: ["network"]
```

## Required environment variables

| Var | Description |
| --- | ----------- |
| `NOTION_TOKEN` | Internal integration secret (`ntn_...` or `secret_...`), unless `token` is passed |

```bash title=".env"
NOTION_TOKEN=ntn_...
```

Create the integration at [notion.so/profile/integrations](https://www.notion.so/profile/integrations),
enable the content capabilities the agent needs, then add it to each page or database through
**•••** → **Connections**.

## Configuration

```ts
new NotionVoice({
  token: process.env.NOTION_TOKEN, // optional; falls back to NOTION_TOKEN
});
```

## Tools

| Tool | Destructive | Description |
|---|---|---|
| `search` | no | Pages and databases whose title matches a query |
| `get_page` | no | A page's title, link and properties as text |
| `get_page_body` | no | A page's body as markdown-like text |
| `query_database` | no | A database's rows, with an optional filter and sorts |
| `create_page` | yes | A new page under a page, or a row in a database, with optional body |
| `append_to_page` | yes | Text added to the end of a page |
| `update_page` | yes | New values for some of a page's properties |
| `archive_page` | yes | The page and everything under it moved to Notion's Trash |

Ids accept 32 hex characters with or without dashes, or a `notion.so` link ending in one. A 404
from Notion comes back telling the agent the page must be shared with the integration.

## Writing formatted pages

`create_page` and `append_to_page` read markdown, so an agent can write a page that looks like
one rather than a column of plain lines:

````md
# Q3 report

Revenue rose **12%**, see [the dashboard](https://example.com/q3).

| Metric | Q2 | Q3 |
| --- | --- | --- |
| Users | 1,050 | 1,200 |

> [!WARNING]
> Churn is up in the EU.

- Next steps
  - Hire two engineers

![Funnel](https://example.com/funnel.png)

```mermaid
graph LR
  Visit --> Signup --> Paid
```
````

That becomes a heading, a paragraph with bold text and a link, a table with a header row, a
yellow warning callout, a nested list, an image and a Notion-drawn diagram. The full syntax:

- `#` to `###` headings; `-`, `1.` and `- [ ]` list items, indented two spaces to nest one level.
- `**bold**`, `*italic*`, `~~strike~~`, `` `code` `` and `[label](https://...)` inside any text.
- GitHub tables. Short rows are padded, long ones cut, and a table over 100 rows is split into
  several, each repeating the header.
- `>` quotes, and `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` or `[!CAUTION]` callouts.
- Code fences; `mermaid` draws a diagram.
- `![caption](https://...)` alone on a line for an image, an `https://` URL alone on a line for a
  bookmark, `---` for a divider.

Image and bookmark URLs must be `https://` on a public host, because Notion's servers fetch them;
a loopback or private address leaves the line as a paragraph. An unclosed marker stays literal.

`get_page_body` renders pages back in the same syntax, tables and callouts included, so content
read from one page can be written to another without losing its formatting.
